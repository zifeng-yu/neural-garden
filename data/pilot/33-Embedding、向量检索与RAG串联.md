# Day 5：Embedding + 向量检索 + RAG 串联

前两天你学了 Encoder 输出向量、Cross Encoder 做精排。今天把这条线彻底打通：文本是怎么变成向量的、向量是怎么被快速搜索的、整条 RAG 链路是怎么串起来的。

## 核心概念（4 个）

### 概念 1：Embedding 的本质（文本 → 向量）

- **是什么**：一个由 Encoder 训练出来的函数，把任意长度的文本映射成一个固定维度的数值向量（比如 768 或 1024 个浮点数），使得**语义相近的文本，向量距离也相近**。
- **解决什么问题**：计算机不认识「意思」，只认识数字。传统的关键词匹配（Day 2 的 BM25）只能处理字面重合，「如何取消订阅」和「不想继续续费怎么办」没有一个共同词，BM25 无能为力。Embedding 把「意思」变成几何位置——这两句话的向量会靠得很近。这是语义检索的地基。
- **输入输出**：输入一段文本，输出一个固定长度的向量。关键点：这个向量不是人工设计的特征，而是模型在海量语料上通过对比学习练出来的——训练时不断拉近「语义相同」的文本对、推开「语义不同」的文本对，几亿次之后，语义关系就编码进了空间结构里。
- **为什么重要**：整个 RAG 系统的「记忆」都存在这个空间里。文档质量、Chunk 切分策略、Embedding 模型选型，三者共同决定你的检索上限——LLM 再强，召回的向量不对，它也只能基于错误材料编故事。

一个程序员视角的类比：Embedding 是一次**有损哈希**，但和 md5 相反——输入变一个标点，md5 结果面目全非；Embedding 则要求输入意思不变时结果尽量不变，意思变了结果按语义距离可预测地移动。

### 概念 2：Cosine Similarity（为什么用夹角不用距离）

- **是什么**：衡量两个向量「方向」的相似度，值是 -1 到 1，等于两向量夹角的余弦值。越接近 1 越相似。
- **解决什么问题**：找到两个语义向量后，怎么定义「相近」？欧氏距离是一个选择，但它对向量长度敏感。而文本 Embedding 的向量长度往往和文本长度、训练时的归一化方式有关，不代表语义。两段话说同一件事，一个长一个短，向量方向一致但长度不同——用夹角就能忽略长度只看「语义方向」，这正是我们想要的。
- **输入输出**：输入两个向量，输出一个标量分数。很多向量库（包括 Chroma 默认）用 L2 距离或内积，但如果 Embedding 模型输出已归一化（模长为 1），余弦相似度和内积在数学上等价，只是排序方向不同。
- **为什么重要**：这解释了调 RAG 时的一个常见坑——如果你换了一个向量长度分布不同的 Embedding 模型，而距离度量没配套调整，检索排序会莫名变差。度和模型是配套的，不是随便选的。

### 概念 3：ANN 与 HNSW / IVF（向量库的引擎室）

- **是什么**：ANN（Approximate Nearest Neighbor，近似最近邻）——在百万级向量里找最相似的 top-K，用「牺牲一点点精度换几个数量级速度」的索引算法。两大主流：**HNSW**（把向量组织成多层「高速公路+小 roads」的图结构，查询从高层入口逐层下探，像导航先走高速再下匝道）和 **IVF**（先把向量聚成若干簇，查询时只扫描最近的几个簇，像图书馆先找对书架再翻书）。
- **解决什么问题**：暴力计算不现实。100 万条向量、每条 1024 维，一次查询要算 100 万 × 1024 次乘加。HNSW 把每次查询的访问点降到几百个，延迟从秒级压到毫秒级。代价是可能漏掉真正的第一名（近似），实践中 top-K 的召回率通常在 95%+。
- **输入输出**：建立索引时输入全部向量，查询时输入一个查询向量 + K，输出最近的 K 个候选及其分数。可调参数：HNSW 的 ef_search（搜多深，越大越准越慢）、IVF 的 nprobe（扫几个簇）——这就是向量库「速度 vs 精度」旋钮的真身。
- **为什么重要**：Chroma、Milvus、Qdrant、pgvector 底层全是这些结构。你以为在用数据库，其实在用一个为「方向相似」特化的多级缓存搜索结构。

### 概念 4：RAG 全流程串联（把 5 天知识穿成一条线）

- **是什么**：检索增强生成 = 先从外部知识库找出相关材料，再把材料塞进 prompt 让 LLM 基于它回答。一条完整链路：

```
离线（建库）:
文档 → Chunk 切分 → Embedding 模型 → 向量 → 存入 Chroma(HNSW 索引)

在线（查询）:
提问 → 同一个 Embedding 模型 → 查询向量
     → ANN 召回 top 50（可叠加 BM25 → RRF 融合 = Hybrid）
     → Reranker(Cross Encoder) 精排 top 5
     → 拼进 prompt → LLM(Decoder) 生成回答
```

- **解决什么问题**：LLM 的两个硬伤——知识截止（训练数据有日期）和幻觉（不知道也敢编）。RAG 把「知识存储」和「语言能力」解耦：知识存在可更新的向量库里，LLM 只负责理解问题+阅读材料+组织语言。改知识不用重训模型，像热更新配置而非重编内核。
- **输入输出**：系统级输入是用户问题，输出是带依据的回答。中间每一步都是一次数据变换，任何一步出错都会向下传导：Chunk 切碎→语义残缺→向量不准→召回垃圾→LLM  garbage in garbage out。
- **为什么重要**：这就是你 AI 系统的骨架。而且注意精妙之处——RAG 是**两个阶段的不对称架构**：粗召回用 Bi Encoder + ANN（快而糙），精排用 Cross Encoder（准而慢），评价用 MRR/NDCG（Day 1）。5 天的概念在这一条链路上全部会师。

## 知识地图位置

```
     ┌────────── RAG 全链路 ──────────┐
     │                                │
  Chunking      Embedding       Vector DB
 (文本切分)   (Encoder→向量)   (Chroma/HNSW)
                    │                │
                    └── Cosine 打分 ──┤
                                     ▼
                            召回 top50 → Rerank top5 → LLM 生成
```

Embedding 是 Day 4「Encoder 路线」的落地产物；ANN 是支撑它的检索引擎；RAG 是把 Day 1-4 所有组件接起来的系统级方案。

## 系统/代码对照

| 概念 | 对应组件 |
|------|----------|
| Embedding 模型 | BGE / text-embedding-3 等 Encoder（入库和查询必须同一个） |
| Cosine Similarity | 向量检索的打分函数（Chroma 的 distance 配置） |
| HNSW | Chroma 默认向量索引 |
| IVF | Milvus/Faiss 常用的分簇索引 |
| 召回→精排 | Vector top50 → bge-reranker top5 → 进 prompt |

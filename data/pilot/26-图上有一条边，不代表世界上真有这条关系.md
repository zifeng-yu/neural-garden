# Day 11｜图上有一条边，不代表世界上真有这条关系

> 日期：2026-09-18
> 预计阅读：20 分钟
> 今日只回答一个问题：在图上，"查得到"和"成立"之间隔着几层？

## 开场：事情从哪里开始失控

（假设场景）演示日。有人向 Neural Garden 提问："RRF 和 Embedding 有什么关系？"图检索立刻返回一条链：RRF ← 混合检索 ← 向量 Embedding。答案生成器花一秒拼出一句"RRF 依赖于 Embedding 的结果"，台下点头——听起来很合理。

演示结束后，一位同事问了三个问题：第一跳的说法写在哪个文档的哪一句？第二跳也有来源吗？还有——图上真的存在 RRF 直接连向 Embedding 的边吗？

没人当场答得上来。路径是完整的，表述是通顺的，但没人分得清：结构、推断、证据，这三层各自在哪一步出了问题。

## 先给结论

图系统里同时存在三层东西，人却经常把它们当成一层：结构层（这两个节点之间有没有直接边）、推断层（一条路径是把若干条边逐条拼接出来的组合断言）、证据层（这条边凭什么存在——哪个文档哪个 chunk 说了这句话）。

"可达"不蕴含"存在直接关系"；"图上有这条边"也不蕴含"世界上这条关系为真"。BFS 找到了路径，路径让句子通顺，系统就把三件事当成了一件事——这是图检索开始说谎的精确位置。

Neural Garden 的 Relation Evidence 设计解决的正是第三层：每条断言都能回溯到 document 和 chunk，这一层已经实现。但前两层更常犯错：把邻接表的 value 当成"可达清单"、把 BFS 的出队顺序当成路径、把两跳拼接当成直接关系。今天重点拆这三个。

## 事情为什么会这样

先回到图最基础的表示：邻接表（Adjacency List，每个节点挂一张"我能直接走到谁"的表）。构造一个 5 节点 6 边的小图：

```
A→B  A→C  B→D（两条证据）  C→E  D→E
```

从 A 做 BFS（广度优先搜索），访问顺序是 A、B、C、D、E。现在问：A 到 E 的路径是什么？正确答案是 A→C→E，两跳。注意两个细节：D 在 E 之前被访问，但 D 不在最短路径上；C 排在 B 后面被访问，却恰恰是路径成员。**访问顺序只记录"谁先出队"，它不携带路径信息。** 真正能重建路径的是每个节点的**前驱指针（predecessor）**——"我是从谁那儿被发现的"：{B←A, C←A, D←B, E←C}。沿着它从 E 往回走，才得到路径。这正是上一轮 Extra Skill 练 BFS 时踩过的坑：访问顺序不等于最终路径，现在把它钉死。

第二层混淆更隐蔽：邻接表的 value 是直接邻居（direct neighbors），不是可达路径集合。`G.neighbors("B")` 返回 `['D']`；可从 B 出发实际能到达的是 {D, E}。把 value 记成"路径表"，多跳查询的语义从第一天就是错的。

写成代码跑一遍（14 行）：

```python
import networkx as nx

G = nx.MultiDiGraph()
G.add_edge("A", "B", ref="doc1#chunk3")
G.add_edge("A", "C", ref="doc1#chunk5")
G.add_edge("B", "D", ref="doc2#chunk1")
G.add_edge("B", "D", ref="doc9#chunk4")    # 同一概念对的两条证据
G.add_edge("C", "E", ref="doc4#chunk2")
G.add_edge("D", "E", ref="doc7#chunk1")

print(list(G.neighbors("B")))        # ['D'] — 直接邻居，不是"能到达的一切"
print(nx.has_path(G, "A", "E"))      # True — 只证明可达，不证明有直接关系
print(nx.shortest_path(G, "A", "E")) # ['A', 'C', 'E'] — 路径靠前驱逐步重建
print(list(G["B"]["D"].keys()))      # [0, 1] — 两条平行边，各自带证据引用
```

第三层：就算路径逐边完全正确，路径也只是**组合断言**——"假如每条边成立，则可推出末边"。而 Neural Garden 的边不是人工标注的事实，是 LLM 从文档里抽取的断言。边会怎么错？抽取错：文档说"RRF 常与向量检索配合使用"，LLM 抽出方向相反的"依赖"；归一化错：概念去重时把"Embedding 模型"和"Embedding 向量"并成一个节点，两个概念的边全挂到同一节点上，路径凭空多出一条暗道；还有把"A 与 B 有关"这种无向弱联系抽成有向强关系。错误沿跳数复合：假设单跳抽取正确率 90%（示意数字），两跳全对约 81%，三跳约 73%——路径越长越震撼，就越不可信。

最后看多重边。MultiDiGraph（多重有向图）允许同一对节点间存在多条平行边（parallel edges），每条携带独立属性。上例 B→D 有两份来源，若折叠成单边，丢掉的不仅是归因，还有"多个独立来源支持同一关系"这一置信信号；反过来，两份证据也可能断言的是不同内容（一份说用途、一份说局限），合并即篡改。

## 把系统画出来

```
┌ 推断层 ── 查询"RRF 与 Embedding 的关系"
│          遍历结果：路径 RRF ← 混合检索 ← Embedding
│          ✗ 失败点③：把两跳拼接当成直接关系
├ 结构层 ── NetworkX MultiDiGraph（运行时从 SQLite 构建，图投影）
│          节点=Concept，边=Relation，平行边各自挂 ref
│          ✗ 失败点②：归一化把不同概念并成一个节点
├ 断言层 ── SQLite 的 concept_relation 行，每行带 evidence_ref
│          ✗ 失败点①：LLM 抽取错、方向错，但可回溯
└ 证据层 ── 原始 Markdown："RRF 融合 BM25 与向量检索的名次"
           ✓ 唯一能终结争论的锚点
```

一次查询要穿过四层，每层都可能引入或放大错误；只有证据层能把错误钉回原句。

## 放回三个项目中看

### ML/DL 概念层

这是本系列 Day 1"看起来不错不算证据"的图版本：prediction 和 label 是两种东西，edge 和 evidence 也是两种东西。后面的 GNN、Graph Embedding 课程都站在这副骨架上——消息沿边传递，一条错边等于一条噪声标注，会把两端节点的特征搅浑。

### Python / AI Backend 工程层

接口契约要区分三种返回：取直接邻居、取路径（含 hop 数与前驱链）、取带证据的关系。若搜索接口只返回 `list[str]`，三种语义就糊在一起。测试同理：只断言"结果非空"的测试，会放过错路径——呼应此前"测试没命中目标路径"的教训，应断言精确路径序列和 `evidence_ref` 存在。

### Neural Garden 项目层

根据任务建立时提供的项目状态快照（非实时检查）：已实现 Concept 提取与归一化、Concept Relation、Relation Evidence（回溯 document 与 chunk）、SQLite 作为结构化事实来源、NetworkX 运行时图投影、embedding 召回后由 LLM 判断概念相同。Graph-Augmented Retrieval 尚未进入默认搜索链路，因此更不能宣称 GraphRAG 有效。今天的知识直接影响一个未来决策：上图检索之前，先回答"边有多准"——需要一份人工抽检的抽取正确率和一组含多跳问题的评估集，用数字决定是否值得投入。

## 最容易踩的两个坑

1. **把可达当关系。** 看到 A→B→C 就输出"A 依赖 C"。修正：多跳结果必须携带中间节点与跳数，生成端只能说"经由 B 的间接关联"，除非证据层存在直接断言。
2. **图能跑通就等于图正确。** 从 SQLite 投影建图不会报错，但边上的错误畅通无阻地进入检索；结构层还是错误的放大器——路径越长显得越有理。修正：检索返回把 `(关系, 跳数, evidence_ref)` 作为强制三元组，答案只引用带证据的关系。

## 面试官可能继续追问

"你的边是 LLM 抽取的，怎么保证图检索结果正确？"

回答骨架：① 先给结论——无法逐条保证，所以设计成"断言到哪、证据跟到哪"，检索输出强制携带 document/chunk 引用，回答引用证据而非"图上有"。② 解释原因——错误有三层来源：抽取错、归一化合并错、多跳组合复合放大，每层对策不同（抽检统计、归一化复核、限制跳数并披露中间节点）。③ 落到项目——Neural Garden 当前默认链路只用向量检索，下一步不是上图检索，而是先做边质量抽检和多跳评估集，有数字再谈 GraphRAG。

## 合上文档前的 60 秒

今天最重要的三句话：

1. 邻居不是路径，访问顺序不是答案，路径不是直接关系。
2. 图上"查到"有三种东西：一条边、一条路径、一条带证据的链——前两种没有断言资格。
3. 图检索能交付的最小诚实单元是（关系, 跳数, evidence_ref）三元组。

## 一、递归到底是什么？

**一句话：递归 = 函数自己调用自己。**

但不是随便调用——它遵循三个铁律：

```
┌─────────────────────────────────────────────┐
│  递归函数的三个组成部分                        │
│                                              │
│  1. 终止条件（base case）                     │
│     → "什么时候不用再调自己？"                │
│                                              │
│  2. 缩小问题（reduce）                        │
│     → "把大问题拆成更小的同类问题"             │
│                                              │
│  3. 组合结果（combine）                       │
│     → "把小问题的答案拼成大问题的答案"         │
└─────────────────────────────────────────────┘
```

**类比：俄罗斯套娃。**
你打开一个套娃 → 里面还有个更小的 → 再打开 → 再打开 → 直到最小的那个（终止条件）→ 然后你从最小的开始，一个一个把套娃合回去（回溯）。

## 二、用你已经学过的题目来理解

### 例1：爬楼梯 G1（最简单的递归）

```
问题：n阶楼梯，每次走1步或2步，有多少种走法？

递归定义：
  f(n) = f(n-1) + f(n-2)
  
终止条件：
  f(1) = 1  （只剩1阶：只能走1步）
  f(2) = 2  （剩2阶：走1+1 或 走2）
```

**n=4 的完整执行过程：**

```
f(4)                        ← 我要算4阶的走法
├── f(3)                    ← 先算从第3阶上来的走法
│   ├── f(2) = 2            ← 终止！直接返回2
│   └── f(1) = 1            ← 终止！直接返回1
│   → f(3) = 2 + 1 = 3      ← 组合：3阶有3种走法
│
└── f(2) = 2                ← 终止！直接返回2
→ f(4) = 3 + 2 = 5          ← 组合：4阶有5种走法 ✅
```

**关键点：每一步都是独立的"函数实例"。**
f(3) 和 f(2) 是不同的调用，各有各的参数、各有各的返回值。它们就像不同的工人，各自算自己的答案，最后汇报给你。

### 例2：汉诺塔 G2（分治递归）

```
问题：把n个盘子从A柱移到C柱（B做辅助）

递归定义：
  hanoi(n, A, B, C) =
    1. hanoi(n-1, A, C, B)   ← 上面n-1个先移到B
    2. 移动第n个（最大的）A→C ← 只有一步
    3. hanoi(n-1, B, A, C)   ← n-1个从B移到C

终止条件：
  n == 1：直接移动，不需要再递归
```

**n=3 的完整执行过程（注意参数的变化）：**

```
hanoi(3, A, B, C)
│
├── hanoi(2, A, C, B)          ← 先把上面2个从A移到B
│   ├── hanoi(1, A, B, C) → A→C   ← 终止！移1个
│   ├── 移动 A→B                   ← 最大那个
│   └── hanoi(1, C, A, B) → C→B   ← 终止！移1个
│
├── 移动 A→C                       ← 最大的盘子到位！
│
└── hanoi(2, B, A, C)          ← 再把2个从B移到C
    ├── hanoi(1, B, C, A) → B→A
    ├── 移动 B→C
    └── hanoi(1, A, B, C) → A→C
```

最终移动序列（7步）：
```
A→C, A→B, C→B, A→C, B→A, B→C, A→C
```

### 例3：斐波那契 J1（理解"重复计算"问题）

```
问题：F(n) = F(n-1) + F(n-2), F(0)=0, F(1)=1

终止条件：
  F(0) = 0, F(1) = 1
```

**朴素递归的问题（n=5）：**

```
          F(5)
        /      \
      F(4)      F(3)
     /    \     /    \
   F(3)  F(2) F(2)  F(1)
   /  \   / \   / \
 F(2) F(1) ... ... ...
 /  \
F(1) F(0)
```

**看到问题了吗？** F(3) 被算了 2 次，F(2) 被算了 3 次！

n=40 时，朴素递归要算超过 10 亿次。这就是为什么我们在斐波那契那题中推荐用迭代（动态规划）——从小到大算，不重复。

**记忆化优化（记住已经算过的）：**

```python
memo = {}

def fib_memo(n):
    if n in memo:           ← 算过就直接返回！
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1) + fib_memo(n-2)  ← 记住答案
    return memo[n]
```

加了记忆化后，每个 n 只算一次，从 O(2ⁿ) 降到 O(n)。

### 例4：员工重要性 I1（DFS递归）

```python
def dfs(id):
    emp = map[id]
    total = emp.importance
    for sub_id in emp.subordinates:
        total += dfs(sub_id)    ← 对每个下属递归
    return total
```

**递归树（员工1有两个下属2和3）：**

```
dfs(1): importance=5
├── dfs(2): importance=3 → 返回 3
└── dfs(3): importance=3 → 返回 3
→ 返回 5+3+3 = 11
```

这就是"深度优先搜索"——先沿一条路走到头（某个下属的所有下属），再回来走另一条路。

## 三、递归思维的核心：信任跳跃

**这是理解递归最关键的一步。**

想象你是一个包工头，接到一个任务。你的工作方式是：

1. **如果任务很简单**（终止条件）→ 自己干完
2. **如果任务比较复杂** → 把活分包给下级包工头，然后 **信任他能干好**

**你不需要知道下级包工头是怎么干的。** 你只需要知道：
- 你给了他正确的子任务
- 他会返回一个正确的答案
- 你把答案拼起来就行了

**这就是"信任跳跃"（Leap of Faith）。** 你不需要在脑子里追踪每一层递归——那会让人疯掉。你只需要关注：
- 这一层的输入是什么？
- 这一层要做什么？
- 这一层要返回什么？

## 四、五个实用要点

### 1. 先写终止条件，再写递归逻辑
```python
def climb_stairs(n):
    if n <= 2:          ← 先写！这是你的安全网
        return n
    # 然后再写递归
    return climb_stairs(n-1) + climb_stairs(n-2)
```

### 2. 追踪参数变化
递归的参数每次都在变。拿汉诺塔来说：
- 第一次：hanoi(3, A, B, C) — 从A到C
- 第二次：hanoi(2, A, C, B) — 从A到B（参数变了！）
- 注意：from、aux、to 三个参数在递归调用中轮换了

### 3. 画递归树
对于小规模输入，画出完整的递归树，标注每一步的返回值。这是最好的练习方式。

### 4. 注意重复计算（斐波那契教训）
如果一个子问题被多次调用，考虑：
- 记忆化（加缓存）
- 或者直接改迭代（动态规划）

### 5. 递归 vs 迭代：什么时候用哪个？
| 场景 | 推荐 | 原因 |
|------|------|------|
| 树/图的遍历 | 递归 | 结构天然递归定义 |
| 分治问题 | 递归 | 思路清晰 |
| 斐波那契/爬楼梯 | 迭代 | 避免重复计算 |
| 汉诺塔 | 递归 | 迭代写法极其复杂 |

# 搜索结果不理想的原因分析

**分析时间**：2026-08-04  
**课程**：Neural Garden Lesson 03 - 向量搜索入门

---

## 问题描述

搜索返回结果不理想，可能表现为：
- 返回结果与查询不相关
- 相关结果排名靠后
- 返回结果太少或太多

---

## 原因分析

### 1. 输入信息不够充分

**问题**：用户查询太短或太模糊。

**示例**：
- ❌ 查询：`"利率"` → 太宽泛，可能匹配到任何利率相关内容
- ✅ 查询：`"日本负利率政策核心逻辑"` → 明确，易于匹配

**解决方案**：
- **查询扩展（Query Expansion）**：添加同义词、相关词
- **多轮对话**：引导用户补充更多上下文
- **示例**：
  ```python
  # 简单查询扩展
  query = "利率"
  expanded_query = "利率 货币政策 央行 负利率"
  ```

---

### 2. 数据文档 Embedding 颗粒度问题

**问题**：数据文档没有 chunk，或混入多主题内容。

**示例**：
- ❌ 一篇 5000 字文档包含多个主题 → Embedding 向量表示模糊
- ✅ 每篇 300-500 字，单一主题 → Embedding 向量表示清晰

**解决方案**：
- **文档 Chunking**：按主题/段落切分文档
- **知识单元提取**：Lesson 02 的 `indexer.py` 已实现
- **示例**：
  ```python
  # 错误：整篇文档作为一个向量
  embed(full_article)  # 5000 字，多主题

  # 正确：按知识单元切分
  embed(title + summary + keywords)  # 200 字，单一主题
  ```

---

### 3. Embedding 模型能力限制

**问题**：通用模型 vs 垂直领域不匹配。

**示例**：
- 通用模型（如 text-embedding-v3）：适合日常文本
- 垂直模型（如金融、法律专用）：适合专业领域

**解决方案**：
- **选择领域匹配的模型**：金融内容用金融 Embedding 模型
- **微调 Embedding 模型**：用领域数据 fine-tune
- **示例模型对比**：
  | 模型 | 适用领域 | 中文优化 |
  |------|---------|---------|
  | text-embedding-v3 | 通用 | ✅ |
  | bge-large-zh | 通用 | ✅ |
  | m3e-base | 中文专用 | ✅ |

---

### 4. 没有 Reranker（重排序）

**问题**：向量搜索只考虑语义相似度，不考虑其他因素。

**解决方案**：
- **添加 Reranker 层**：
  ```
  用户查询 → 向量搜索（召回 100 条）→ Reranker（重排序）→ 返回 Top 10
  ```
- **Reranker 可以考虑**：
  - 关键词匹配度（BM25）
  - 文档新鲜度
  - 文档权威性
  - 用户行为反馈

**示例工具**：
- Cohere Rerank
- BGE Reranker
- 自训练 Reranker 模型

---

### 5. 阈值设置问题

**问题**：阈值过高或过低。

| 阈值 | 效果 | 适用场景 |
|------|------|---------|
| 0.5 | 结果多，质量参差不齐 | 探索性搜索 |
| 0.7 | 平衡 | 默认推荐 |
| 0.9 | 结果少，但精准 | 精准匹配 |

**解决方案**：
- **动态阈值**：根据查询长度/领域调整
- **用户反馈**：记录用户对结果的点击/跳过行为

---

## 综合解决方案

**推荐流程**：

```
用户查询
    ↓
查询扩展（同义词、相关词）
    ↓
向量搜索（召回 50-100 条）
    ↓
Reranker 重排序（考虑 BM25 + 新鲜度 + 权威性）
    ↓
阈值过滤（默认 0.7）
    ↓
返回 Top 10
```

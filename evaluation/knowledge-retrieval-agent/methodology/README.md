# 知识检索 Agent 评估方法

按“选工具 → 检索 → 读取原文 → 回答 → 追问”检查执行过程，不能只看最终答案是否像正确答案。

| 检查项 | 判定口径 |
|---|---|
| 工具选择 | 知识问题是否使用 search_knowledge；普通问候是否避免不必要检索 |
| 原文读取 | 回答证据是否来自 read_chunk，而非仅凭知识单元摘要 |
| 参数关联 | read_chunk 的 document_id/chunk_id 是否对应实际结果，不编造 ID |
| 引用一致 | D文档:C片段编号与实际读取结果一致 |
| 语义支持 | 原文是否支持断言、限定条件与因果解释 |
| 多轮追问 | 同一 thread 的追问能否回到正确原文；不同会话不能混用历史 |
| 拒答 | 无相关证据时是否说明不足，追问后仍保持证据边界 |

后续批量运行可分别计算工具选择正确率、引用一致率、语义支持率、追问通过率与无答案拒答率，分母必须是对应类型的有效用例。当前只有少量人工观察，没有按统一口径给出总体比例。

每轮应保存问题、thread_id、工具名/参数/结果、最终回答、证据 hash、模型与提示词版本。当前 tests/test_agent_graph.py 主要验证图执行和状态行为，不等于真实模型的工具选择和回答质量评估。
